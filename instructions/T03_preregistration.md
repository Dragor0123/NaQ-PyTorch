## 해석상 주의 (사전 명시)

1. **Oracle은 순도와 test 클래스 레이블 노출이 섞인 상한이다.**
   - 앵커를 전체 노드에서 뽑으므로 way의 일부(약 20–25%)가 test 클래스다. 그 순수 query는 test 클래스 구조를 직접 가르친다.
   - 따라서 G2 통과(P10)가 곧바로 "순도가 병목"이라는 뜻은 아니다.
   - 순도만의 효과를 보려면 test 클래스 노출이 없는 대조군이 필요하다 (아래 선택 arm).
2. NaQ-best는 데이터셋마다 결과를 보고 고른 값이다. `lr_only`·`cape_lite`는 고르지 않은 단일 설정이다.
3. seed 1개, test 태스크 500개 기준으로 1.5%p 미만의 차이는 잡음 범위로 본다.

## 선택 arm (사용자 결정 시 추가): `oracle_base`

- 정의: 앵커를 **base 클래스 노드에서만** 뽑는다 (서로 다른 레이블 5개). query는 같은 레이블 노드를 R* 순으로 top-10 고른다.
- 성격
  - 생성기 입장에서 base 레이블만 쓰므로 CaPE에서 허용되는 정보다.
  - 이는 s̃(레이블 영역의 정확 affinity)를 base 앵커에 적용한 경우와 같다.
- 비용: 데이터셋당 run 1회, 총 약 6–8분 추가

|---|---|---|---|---|
| P15 | base에 한정된 순수 에피소드는 NaQ-best를 넘지 못한다 | `oracle_base` − NaQ-best: eletronics −5 ~ +1, dblp −3 ~ +2 | 0.65 | NaQ의 Sup ProtoNet(base 클래스, 순수)이 eletronics에서 NaQ-Feat보다 7%p 낮음. 전체 노드 활용의 이점이 순도보다 큼 |
